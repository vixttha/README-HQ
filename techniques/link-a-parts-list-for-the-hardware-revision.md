# Link a parts list for the hardware revision

**Use when.** Hardware builds differ by revision, assembly variant, or optional part.

**Reader task.** Quickstart and adoption.

**Practice.** Give builders a bill of materials that matches the design they are assembling. Include part identifiers, quantities, and any documented substitutions, with a way to map each item to the design.

**Example (illustrative).** Link the rev-B assembly list with quantities and connector part numbers.

**Result to check.** A builder can match each part and variant to the board revision they have.

**Evidence.** Research reference. Run the reader check on the target project before relying on the documented outcome.

**Research references.** [OSHWA documentation checklist](https://certification.oshwa.org/process/documentation.html)
