# Explain how to choose an update channel

**Use when.** The project publishes parallel release channels with different update expectations.

**Reader task.** Purpose and audience.

**Practice.** When multiple release streams are offered, state the differences in stability, update cadence, and what the reader should install. nginx labels mainline, stable, and legacy downloads.

**Example (illustrative).** Use Stable for normal installs or Preview to try unfinished features with a separate configuration.

**Result to check.** A reader can choose a channel and find its update or rollback path.

**Evidence.** Research reference. Run the reader check on the target project before relying on the documented outcome.

**Research references.** [nginx release channels](https://nginx.org/en/download.html)
