# Identify required assets distributed separately

**Use when.** A clean checkout omits assets required for the first run.

**Reader task.** Quickstart and adoption.

**Practice.** State which graphics, sound, models, or other runtime assets the checkout needs. Link their maintained source and say which installation routes fetch them automatically.

**Example (illustrative).** List the separately downloaded dataset filename, matching version, and expected destination.

**Result to check.** A clean checkout succeeds once the documented external files are staged in place.

**Evidence.** Research reference. Run the reader check on the target project before relying on the documented outcome.

**Research references.** [OpenTTD’s base assets](https://github.com/OpenTTD/OpenTTD/blob/e8a7f94481f0a545715b221c8ae63271b60df98b/README.md#L64-L84)
