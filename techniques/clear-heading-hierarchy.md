# Clear heading hierarchy

**Use when.** The README has several sections or deeply nested material.

**Reader task.** Navigation and accessibility.

**Practice.** Organize sections in a predictable structure for visual scanning and assistive navigation.

**Example (illustrative).** Give Quickstart and Troubleshooting second-level headings with task steps under third-level headings.

**Result to check.** The rendered heading outline reflects the document structure without skipped nesting.

**Evidence.** Research reference. Run the reader check on the target project before relying on the documented outcome.

**Research references.** [Google heading structure guidance](https://developers.google.com/style/headings)
