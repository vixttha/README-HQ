# Link directly to a project-configured workspace

**Use when.** The project can supply a known workspace configuration for first-time users.

**Reader task.** Quickstart and adoption.

**Practice.** Point readers to a preconfigured development workspace tied to the repository and intended branch. State what account or local tooling it needs. GitHub Codespaces and VS Code Dev Containers document repository links for this.

**Example (illustrative).** Open the repository’s development container using a workspace link that selects the correct config.

**Result to check.** A fresh user reaches a ready terminal and can run the first command.

**Evidence.** Research reference. Run the reader check on the target project before relying on the documented outcome.

**Research references.** [Codespaces deep links](https://docs.github.com/en/codespaces/setting-up-your-project-for-codespaces/setting-up-your-repository/facilitating-quick-creation-and-resumption-of-codespaces) · [VS Code Dev Containers](https://code.visualstudio.com/docs/devcontainers/create-dev-container)
