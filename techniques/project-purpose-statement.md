# State the project’s purpose

**Problem.** Readers should be able to identify the project before they scan its tooling, status labels, or setup.

**Practice.** Place a plain-language sentence under the title. Name the kind of project, its main action, and the result the reader gets. Add the intended audience if the same description could attract someone the project cannot serve.

**Example.** Veraphify describes looking up the exact commit, file, and line behind a feature in a selected version. That tells a reader what question the tool can answer.

**Limits.** Project slogans, release labels, and feature lists can follow. A generic description that fits several unrelated products needs a more specific task or outcome.

**Result to check.** Ask a new reader to explain what the project can do after reading the title and first paragraph.

**Evidence.** Observed in the cited guidance or example.
