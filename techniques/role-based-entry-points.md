# Route by reader task

**Use when.** Different readers arrive with different first tasks and need clear starting routes.

**Problem.** A project can have readers who want to use it, develop it, or troubleshoot it. A single generic starting route may send them to the wrong setup.

**Practice.** Put the common first task first, and give each materially different task a short link with a destination readers can predict. State any platform or access boundary in the label or beside it.

**Example.** AlderVale presents distinct routes for the Windows launcher, starting from source, and making the first playthrough.

**Limits.** Use separate routes when the reader’s steps differ. A tiny project with one onboarding path can use one prominent route.

**Result to check.** Give a new reader a task and ask them to choose the correct link without opening every route.

**Evidence.** Observed in the cited guidance or example.
