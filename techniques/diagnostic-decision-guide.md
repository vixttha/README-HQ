# Diagnostic decision guide

**Use when.** Similar errors require different checks or remedies.

**Reader task.** First result and recovery.

**Practice.** Route different symptoms to the relevant fix instead of listing generic troubleshooting.

**Example (illustrative).** If the UI opens but no data appears, check the endpoint before inspecting parsing logs.

**Result to check.** Each listed symptom leads to a distinguishing check followed by a specific action.

**Evidence.** Illustrative practice. Add a project example or test result when this technique is evaluated.
